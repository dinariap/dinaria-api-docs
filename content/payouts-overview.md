# Payouts Overview

A payout is an instruction to send funds from your available account balance to a beneficiary through a supported destination and payout rail.

> Before creating a payout, make sure your account is prefunded with sufficient available balance in the source currency. Funding and payouts are separate processes; this section does not describe how funds are deposited.

## What a payout represents

The Payout resource is generic. It can support remittances, supplier payments, user withdrawals, disbursements, settlements, and other outbound money movements. Country-specific examples only illustrate the beneficiary and rail data required for a particular corridor.

| Concept | Description |
|---|---|
| `source` | Amount and currency debited from the available balance. |
| `destination` | Destination country, currency, beneficiary, and payout rail. |
| `beneficiary` | Person or business receiving the funds. |
| `rail` | Country-specific delivery method. |
| `remitter` | Entity initiating the transfer, when required by the corridor. |
| `externalId` | Stable payout reference assigned by your system. |
| `payoutId` | Canonical identifier generated by Dinaria. |
| `Idempotency-Key` | Technical request identifier used to prevent duplicate submissions. |
| `metadata` | Client-owned data returned unchanged. |

`externalId` and `Idempotency-Key` serve different purposes. Required beneficiary, remitter, and rail fields depend on the active country and corridor.

## General flow

```text
Prefunded available balance
          ↓
POST /v2/payouts
          ↓
     processing
      ├── confirmed ──→ reversed
      ├── failed
      └── cancelled
```

The `payout.created` event means the payout was durably accepted and persisted. The resource itself starts in `processing`.

## Public statuses

| Status | Meaning |
|---|---|
| `processing` | Accepted and executing; the final outcome is not known yet. |
| `confirmed` | Final delivery was confirmed. |
| `failed` | Definitive failure before delivery. |
| `cancelled` | Processing stopped before delivery. |
| `reversed` | A previously confirmed outbound transfer was subsequently returned. |

## Public dates

| Field | Meaning |
|---|---|
| `creationDate` | When Dinaria created the payout. |
| `confirmationDate` | When final delivery was confirmed. |
| `failureDate` | When the payout definitively failed. |
| `cancellationDate` | When the payout was cancelled. |
| `reversalDate` | When a previously confirmed transfer was returned. |

## Balance and funds

The payout is created against the available source-currency balance. Keep the account prefunded before submitting it. Internal debit, compensation, routing, reconciliation, and connector states are not exposed by the public API.
