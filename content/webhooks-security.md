# Webhook security & signature verification

All webhook events are signed so you can verify their authenticity and integrity.

**Always verify the signature before processing any webhook event.**

---

## Headers

| Header | Description |
|--------|-------------|
| `X-Webhook-Id` | Event identifier; matches `eventId` in the payload. |
| `X-Webhook-Timestamp` | Unix timestamp (seconds) |
| `X-Webhook-Signature` | Signature header (see format below) |

Example (normal):

```http
X-Webhook-Id: <EVENT_UUID>
X-Webhook-Timestamp: 1737000000
X-Webhook-Signature: t=1737000000,v1=9d0c...ab12
```

Example during secret rotation (multiple valid `v1` signatures may be present):

```http
X-Webhook-Id: <EVENT_UUID>
X-Webhook-Timestamp: 1737000000
X-Webhook-Signature: t=1737000000,v1=9d0c...ab12,v1=3e7f...cc99
```

---

## Signature algorithm

**Signed payload:**

```
<timestamp>.<raw_body>
```

**Signature:**

```
HMAC_SHA256(webhookSecret, signed_payload)
```

The digest is encoded as lowercase hexadecimal.

Use the exact raw HTTP request body received from Dinaria. Do not parse and reserialize the JSON before calculating the signature, because even equivalent JSON can produce different bytes.

> The full secret string including the `whsec_` prefix is used as the HMAC key.

---

## Verification rules

1. Extract `t` and every `v1` value from `X-Webhook-Signature`.
2. Reject if `|now - t| > 300` (5 minutes).
3. Compute `HMAC_SHA256(secret, "<t>.<raw_body>")`.
4. Compare the expected digest with each `v1` using **constant-time comparison**.
5. During secret rotation, accept any valid `v1` signature generated by an active secret.
6. Reject if none of the signatures are valid.

After signature verification, process `eventId` idempotently. Reject timestamps outside a reasonable tolerance to reduce replay attacks, and never use a normal string equality operation for signature comparison.

When rotating through `POST /v2/webhooks/{webhookId}/rotate-secret`, the previous secret remains valid for 24 hours. During that window, accept a valid signature from either active secret and remove the previous secret from your verifier after the overlap ends.

## Code examples

### Node.js

```javascript
const crypto = require('crypto');

function verifyWebhook(rawBody, signatureHeader, secret) {
  const parts = signatureHeader.split(',').map(p => p.split('=', 2));
  const timestamp = parts.find(([key]) => key === 't')?.[1];
  const signatures = parts
    .filter(([key]) => key === 'v1')
    .map(([, value]) => value);
  if (!timestamp) return false;

  // Reject stale events (±5 minutes)
  if (Math.abs(Date.now() / 1000 - parseInt(timestamp)) > 300) return false;

  const signed = `${timestamp}.${rawBody}`;
  const expected = crypto
    .createHmac('sha256', secret)
    .update(signed)
    .digest('hex');

  return signatures.some(signature => {
    const expectedBytes = Buffer.from(expected, 'hex');
    const receivedBytes = Buffer.from(signature, 'hex');
    return expectedBytes.length === receivedBytes.length &&
      crypto.timingSafeEqual(expectedBytes, receivedBytes);
  });
}
```

### Python

```python
import hashlib, hmac, time

def verify_webhook(raw_body: bytes, signature_header: str, secret: str) -> bool:
    parts = [p.split('=', 1) for p in signature_header.split(',')]
    timestamp = next((value for key, value in parts if key == 't'), None)
    signatures = [value for key, value in parts if key == 'v1']
    if not timestamp:
        return False

    # Reject stale events (±5 minutes)
    if abs(time.time() - int(timestamp)) > 300:
        return False

    signed = f"{timestamp}.{raw_body.decode()}".encode()
    expected = hmac.new(secret.encode(), signed, hashlib.sha256).hexdigest()
    return any(hmac.compare_digest(expected, value) for value in signatures)
```
